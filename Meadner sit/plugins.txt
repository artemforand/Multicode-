MEANDER — API ПЛАГИНОВ (SDK 1)
Справочник для автора плагина и для нейросети, которая плагин пишет.
Актуально на 2026-09-24. Полная версия с ссылками на исходники:
docs/plugin-api.md в репозитории; живые примеры — plugins/examples/*.

==========================================================================
0. КАК ЭТИМ ПОЛЬЗОВАТЬСЯ (прочитать первым)
==========================================================================

Вы просите ИИ: «сделай плагин Meander по справочнику ниже». Задача ИИ — выдать
РОВНО ДВА ФАЙЛА:

  my-plugin/plugin.json   — манифест
  my-plugin/main.lua      — логика (имя может быть другим, оно в entry)

Правила, которые ИИ обязан соблюдать, иначе плагин не установится:

  * Неизвестных полей в манифесте быть не может: опечатка в имени поля =
    ошибка установки, а не «забыли и молча пропустили».
  * Обработчики кнопок — только ГЛОБАЛЬНЫЕ функции по имени
    (function openPage() ... end). local function не найдётся никогда.
  * В UI-спеке свойства — только скаляры (число, строка, bool) плюс children и
    row. Никаких вложенных объектов-стилей: валидатор их отклоняет.
  * Нативного кода, файлов и сети у плагина нет и не будет. Есть только Lua и
    декларативный JSON.
  * Хранилище плагина одно на всё приложение: каждый ключ начинать с
    mnd.questId, иначе прогресс из одного квеста протечёт в другой.

После установки плагин виден в «Плагины», а ошибки валидации показываются в UI
текстом — молчаливого отказа нет. Если плагин не поднялся, читают текст ошибки
и правят манифест/спек.

==========================================================================
1. ЧТО ТАКОЕ ПЛАГИН
==========================================================================

Плагин — папка с plugin.json и Lua-точкой входа. Он описывает НАМЕРЕНИЯ:
какие команды выполнить и какой UI нарисовать. Исполняет и рисует движок.

Из этого следует:
  1. Плагин не присылает код в Dart. Наружу уходит только JSON: список команд
     фиксированного набора (toast / render / close / goto_node / play_sound /
     stop_audio), дифферент переменных и снимок хранилища.
  2. UI — дерево из конечного алфавита типов (§7), прогнанное через валидатор
     ядра до рендерера.

Хост живёт в Rust и он один на процесс: установка плагинов — свойство
приложения, а не игровой сессии. Состояние Lua (mnd.vars.* — переменные квеста,
mnd.storage.* — своё хранилище) переживает переходы между нодами.

Установка: «Плагины» → «Импортировать плагин» → выбрать plugin.json или .zip с
плагином внутри. Для распространения — архив .zip с папкой плагина.

==========================================================================
2. МАНИФЕСТ plugin.json
==========================================================================

camelCase. Все поля ниже — единственные разрешённые.

  id            string  ОБЯЗАТЕЛЬНО  не меньше двух сегментов строчными
                                     латинскими буквами через точку:
                                     my.stuff.counter
  name          string  ОБЯЗАТЕЛЬНО  имя для человека
  version       string  ОБЯЗАТЕЛЬНО  любая непустая строка
  sdk           string  ОБЯЗАТЕЛЬНО  строго "1"; другое значение — отказ
  entry         string  ОБЯЗАТЕЛЬНО  относительный путь к *.lua; "..",
                                     абсолютные пути и "\" запрещены
  description   string  нет          метаданные каталога
  author        string  нет          метаданные каталога
  icon          string  нет          имя Material-иконки
  tags          string[] нет         для поиска в каталоге
  permissions   string[] нет         подмножество: ui quest navigation
                                     audio storage events (§3)
  hooks         string[] нет         события (§5) или custom.*; дубликат и
                                     неизвестное имя — ошибка
  contentTypes  объект[] нет         новые типы контента редактора (§9)
  slots         объект[] нет         области UI, где плагин рисует

slots[]: { "id": "...", "area": "...", "priority": N }
  area: hud (правый верх) | overlay (центр) | drawer (низ) | menu (левый край)
  priority меньше — выше/левее внутри области.

Пример:

{
  "id": "mnd.examples.statushud",
  "name": "Панель статуса",
  "version": "1.0.0",
  "sdk": "1",
  "entry": "main.lua",
  "description": "HUD со шкалами HP и энергии.",
  "author": "Meander",
  "icon": "heart",
  "tags": ["example", "hud", "ui"],
  "permissions": ["ui", "quest"],
  "hooks": ["quest_start", "node_enter", "item_press"],
  "slots": [
    { "id": "status", "area": "hud", "priority": 10 },
    { "id": "details", "area": "overlay", "priority": 20 }
  ]
}

==========================================================================
3. РАЗРЕШЕНИЯ
==========================================================================

Право проверяется на КАЖДОМ вызове mnd.*. Без права вызов не игнорируется
тихо — Lua получает ошибку, она попадает в errors диспатча и в отладочную
панель. Запрашивайте минимум.

  ui           mnd.ui.toast / render / close
  quest        mnd.vars.* — чтение и запись переменных квеста
  navigation   mnd.game.go(node)
  audio        mnd.audio.play / stop
  storage      mnd.storage.* — своё персистентное хранилище
  events       mnd.emit(name, payload) — рассылка другим плагинам

Права filesystem, network, shell не существуют: плагин физически не может
прочитать файл или уйти в сеть.

==========================================================================
4. LUA API
==========================================================================

Глобальный объект mnd:

  mnd.log.info(text) / warn / error      в отладочную панель, право не нужен
  mnd.vars.get(name)   -> value|nil      право quest
  mnd.vars.set(name, value)              право quest; значение уходит в квест
  mnd.vars.has(name)   -> bool
  mnd.vars.keys()      -> string[]
  mnd.ui.toast(text, durationMs?)        право ui
  mnd.ui.render(target, spec)            право ui; target см. §6
  mnd.ui.close(target)                   право ui
  mnd.game.go(nodeId)                    право navigation
  mnd.audio.play(asset, volume?)         право audio
  mnd.audio.stop(asset?)                 право audio; без asset — всё
  mnd.storage.get(key)   -> value|nil    право storage
  mnd.storage.set(key, value)
  mnd.storage.delete(key)
  mnd.storage.keys()     -> string[]
  mnd.on(event, function(payload) end)   подписка внутри плагина
  mnd.emit(name, payload)                право events
  mnd.cancel()                           только у отменяемого события
                                        (node_enter)

Контекст вызова (перезаписывается перед каждым хуком):

  mnd.pluginId, mnd.pluginName  кто я
  mnd.contractVersion           "0.1"
  mnd.event                     имя текущего события, '' вне хука
  mnd.questId, mnd.nodeId       где я; nodeId пуст до первой ноды
  mnd.now                       мс с эпохи на момент вызова
  mnd.payload                   payload события таблицей, nil вне хука

Из песочницы изъяты io, os, package, require, debug, load, loadstring, print,
dofile. Доступны string, table, math.

==========================================================================
5. СОБЫТИЯ И ХУКИ
==========================================================================

Доступные события (EventContract v0.1):

  quest_start   { quest_id }              до рендера первой ноды, однократно
  quest_end     { quest_id }              после закрытия сессии, однократно
  quest_save    { slot_id, autosave }     после записи слота
  quest_load    { slot_id, from_save }    до рендера восстановленной ноды
  node_enter    { node_id }               до дефолтной инициализации ноды;
                                          ЕДИНСТВЕННОЕ, где доступен
                                          mnd.cancel()
  node_exit     { node_id }               после выхода из ноды
  item_reveal   { node_id, item_id, item_json }
                                          после раскрытия айтема; сюда плагин
                                          получает поля своего content type в
                                          item_json.pluginData
  item_press    { node_id, item_id, trigger }
                                          до обработки нажатия
  transition    { from, to }              после резолюции перехода
  audio         { kind, asset, volume, ... }
                                          зеркало аудио-команды
  custom.<имя>  своя фамилия; их эмитит только сам плагин через mnd.emit

На событие реагируют И функции, зарегистрированные через mnd.on, И глобальная
функция on_<событие>: on_quest_start, on_node_enter, on_item_reveal, …
Достаточно объявить хук в манифесте — и ядро не дёргает плагин на событиях,
которые ему не нужны.

Колбэки UI (onPress: 'имя') разрешаются как ГЛОБАЛЬНАЯ функция по имени.
Аргумент приходит одним значением (см. §7 про args).

==========================================================================
6. КУДА РИСОВАТЬ: МИШЕНИ
==========================================================================

mnd.ui.render(target, spec):

  slot:<id>   слот из манифеста. Слот, которого нет в манифесте, — ошибка.
  item:<id>   контент конкретного айтема (type: 'plugin', §9). Такие
              поверхности живут РОВНО ОДНУ НОДУ: при переходе плеер их снимает,
              чтобы «инвентарь» из старой сцены не висел в новой.
  screen      модалка на весь игровой экран поверх слотов — заставка,
              самостоятельная головоломка, витрина. Переживает смену ноды и
              снимается или плагином (mnd.ui.close('screen')), или игроком —
              крестиком, который рисует клиент. Цель screen одна на
              приложение: последний отрендеривший плагин выигрывает.

Области слотов hud / overlay / drawer / menu монтируются в игровом экране все
четыре; пустая область не рисует ничего.

==========================================================================
7. UI-СПЕК
==========================================================================

Типы виджетов (22):

  column row stack box card list grid scroll text heading caption badge icon
  image input button chip switch slider progress divider spacer

Дети (children) разрешены только контейнерам: column row stack box card list
grid scroll. У list/grid дополнительно row (он же item) — шаблон ОДНОЙ строки,
а сами данные — в items.

Свойства — только скаляры плюс children и row. Массив разрешён, но внутри
массива тоже только скаляры.

  text        текст/heading/caption/badge/chip  надпись
  label       button/chip/switch/slider/badge    подпись (button понимает text)
  size        текст, иконка, бейдж, spacer       pt / px
  color, background, border                      имя цвета или #RRGGBB /
                                                 #AARRGGBB
  radius, padding, opacity                       везде, кроме card/box/stack
                                                 (они красят себя)
  width, height                                  листовые виджеты; card/box/
                                                 stack игнорируют width
  weight, bold, maxLines                         текст; weight 100…900 или
                                                 'bold'
  align       контейнеры и дети stack            start end center stretch top
                                                 bottom topStart bottomEnd
  justify     column row                         center end space
  gap         column row list grid card          px
  fill        column                             true — занять всю высоту
  expand      любой узел внутри column/row       true → Expanded
  items       list grid                          литерал-массив или '{имя}'
  columns, ratio                                 grid: 1…6 и соотношение
                                                 сторон ячейки
  cellWidth                                      grid: минимальная ширина
                                                 ячейки в px — адаптивные
                                                 колонки (§8.4)
  icon, name  icon button chip image             имя из конечного списка:
                                                 heart star key lock gear bag
                                                 book coin clock check cross
                                                 eye map person sound bulb
                                                 fire drop flag note
  src, path, asset, fit                          image: путь, имя ресурса или
                                                 uuid; fit = cover contain
                                                 fill tile
  placeholder, password, multiline, maxLength    input
  value, max, min, checked                       progress slider switch
  variant     button                             outline, text
                                                 (по умолчанию filled)
  thickness   divider                            px
  x, y        ребёнок stack                       абсолютная позиция в px
  args        носитель колбэка                   уходит в функцию с именем
  onPress, onTap, onChange, onSubmit             ИМЯ ФУНКЦИИ, не код

Имена цветов: white black red green blue yellow orange purple pink cyan gray
brown gold silver.

--------------------------------------------------------------------------
7.1. Привязка к переменным
--------------------------------------------------------------------------

Строковые свойства проходят подстановку {имя} — тот же синтаксис, что в тексте
квеста, плюс путь по полям и индексам: {inv.slots[2].name}. Работает и для
чисел:

  { "type": "progress", "value": "{hp}", "max": "{hpMax}" }

полоска живёт без единой строчки кода на клиенте.

Неизвестная переменная остаётся в UI как {hp} — опечатка видна, а не
превращается в пустоту. Булевы выводятся как да/нет.

args и icon подставляются так же, как текст. В шаблоне строки args = '{key}'
даёт идентификатор текущего элемента — это ЕДИНСТВЕННЫЙ способ различить
кнопки внутри list/grid: без подстановки все ячейки звали бы одну функцию с
одним и тем же литералом.

Внутри row-шаблона list/grid поля элемента перекрывают переменные квеста:
элемент {"name": "ключ", "count": 2} с шаблоном
{ "type": "text", "text": "{name} × {count}" } даёт «ключ × 2». Для скалярного
списка доступны value и index.

--------------------------------------------------------------------------
7.2. Поле ввода
--------------------------------------------------------------------------

input — единственное, что даёт плагину текст от игрока:

  {
    type = 'input',
    placeholder = 'код',
    value = '{typed}',        -- начальное содержимое и привязка к переменной
    maxLength = 4,
    password = true,          -- скрытый ввод
    args = itemId,            -- чтобы различать поля одной поверхности
    onChange = 'typing',      -- на каждый символ
    onSubmit = 'submit',      -- на Enter
  }

Колбэк получает таблицу: { value = 'набранное', args = '<из спеки>' }. Если
args был объектом, его ключи сливаются с value.

value — однонаправленная привязка: пока поле не в фокусе, им владеет спека, а
во время ввода игрока клиент не трогает содержимое и курсор. Поэтому onChange
обычно только зеркалит текст в переменную и НЕ перерисовывает поверхность:
перерисовка на каждом символе стоила бы фокуса.

--------------------------------------------------------------------------
7.3. Адаптивная сетка
--------------------------------------------------------------------------

Плагин не видит метрик экрана: у песочницы нет ни ширины вьюпорта, ни
медиа-запросов. Адаптируется рендерер, плагин задаёт минимум — cellWidth:

  {
    type = 'grid',
    items = '{bag_items}',   -- сетка привязана к переменной квеста
    columns = 5,             -- потолок: больше пяти колонок не будет никогда
    cellWidth = 104,         -- а меньше — сколько не влезает
    gap = 8,
    ratio = 0.72,
    row = { type = 'button', label = '{name}', icon = '{icon}',
            args = '{key}', onPress = 'examine' },
  }

Колонок берётся floor((ширина + gap) / (cellWidth + gap)), но не больше
columns и не меньше одной. Без cellWidth — ровно columns, и на телефоне ячейки
сплющиваются. Если кнопки не хватает по ширине, рендерер сам убирает иконку и
оставляет подпись с ellipsis.

==========================================================================
8. ТИПЫ КОНТЕНТА (contentTypes)
==========================================================================

Это новые виды содержимого ноды, которых нет в движке: «комбинационный замок»,
«дневник», «радиоприёмник». Поля — форма и данные, не код:

"contentTypes": [
  {
    "id": "combinationLock",
    "name": "Комбинационный замок",
    "description": "Айтем с клавиатурой: код открывает ноду.",
    "icon": "lock",
    "fields": [
      { "key": "code", "label": "Код", "type": "text", "default": "1337" },
      { "key": "targetNode", "label": "Куда вести", "type": "text" }
    ]
  }
]

type поля: text number bool select color asset
  (+ options для select, min/max и hint для number).

Полный тип содержимого — <pluginId>:<id>. Он появляется в «добавить контент»
на узле, в ряду/колонке и в стеке; форма строится из fields, кода в редакторе
нет. Незаполненное поле уезжает с default (без default: text — пустая строка,
number — min/0, bool — false, select — первая опция).

В плагине: айтем узнаёт себя по pluginTypeId и получает заполненные поля в
payload.item_json.pluginData в момент item_reveal.

9. ЛИМИТЫ
==========================================================================

Жёсткие, превышение — ошибка конкретного плагина в этом проходе; квест
продолжает работать, геймдлуп не падает.

  команд за один вызов ............ 64
  записей лога за вызов ........... 100
  узлов в UI-спеке ............... 400
  глубина спека ................... 24
  свойств на узел ................. 22
  детей / длина массива ........... 64
  длина строки .................. 2000
  payload ....................... 64 KiB
  ключей в хранилище ............. 256
  размер значения в хранилище .... 16 KiB
  Lua-памяти на плагин ........... 16 MiB
  Lua-инструкций за вызов .... 5 000 000
  вложенность mnd.emit ............. 4

Бюджет инструкций нужен, чтобы while true do end не подвесил игровой цикл.

==========================================================================
10. ШАБЛОН: МИНИМАЛЬНЫЙ РАБОЧИЙ ПЛАГИН
==========================================================================

my-counter/plugin.json:

{
  "id": "my.counter",
  "name": "Счётчик",
  "version": "1.0.0",
  "sdk": "1",
  "entry": "main.lua",
  "description": "Считает открытия сцены и показывает счётчик в углу.",
  "author": "Ваше имя",
  "permissions": ["ui", "quest", "storage"],
  "hooks": ["quest_start", "node_enter"],
  "slots": [
    { "id": "counter", "area": "hud", "priority": 30 }
  ]
}

my-counter/main.lua:

-- Счётчик посещений сцены. Права: ui (нарисовать), quest (переменная),
-- storage (пережить переустановку квеста).

local STORE_PREFIX = 'mnd.questId'   -- хранилище одно на приложение!

local function storageKey()
  return tostring(mnd.questId) .. '.counter'
end

local function current()
  local value = mnd.vars.get('visits')
  if type(value) == 'number' then return value end
  if type(value) == 'string' then return tonumber(value) or 0 end
  return 0
end

local function render()
  mnd.ui.render('slot:counter', {
    type = 'card',
    align = 'stretch',
    background = '#1B1B22',
    border = '#3A3A46',
    radius = 16,
    padding = 12,
    gap = 6,
    children = {
      { type = 'badge', label = 'Сцена', background = '#26262F',
        color = 'gray', radius = 8 },
      -- Значение подставляет рендерер: перерисовка не нужна, чтобы число
      -- обновилось, но мы перерисовываем сами на каждый вход в ноду.
      { type = 'heading', text = 'Открытий: {visits}', color = 'white' },
      { type = 'button', label = 'Забыть', variant = 'outline',
        color = 'white', border = '#3A3A46', onPress = 'reset' },
    },
  })
end

function on_quest_start()
  if not mnd.vars.has('visits') then
    mnd.vars.set('visits', mnd.storage.get(storageKey()) or 0)
  end
  render()
end

function on_node_enter()
  mnd.vars.set('visits', current() + 1)
  mnd.storage.set(storageKey(), current())
  render()
end

-- Обработчик кнопки обязан быть ГЛОБАЛЬНОЙ функцией.
function reset()
  mnd.vars.set('visits', 0)
  mnd.storage.set(storageKey(), 0)
  mnd.ui.toast('Счётчик сброшен', 1500)
  render()
end

==========================================================================
11. ЧАСТЫЕ ОШИБКИ (что ИИ должен проверить сам)
==========================================================================

  1. onPress = 'openPage', а openPage объявлена как local function → кнопка
     мёртвая. Только глобальная функция.
  2. В манифесте лишнее или переименованное поле (authorName вместо author) →
     установка падает. Это правильно: тихой потери настройки не бывает.
  3. Свойство-объект в спеке ("style": { "color": "red" }) → валидатор
     отклоняет. Цвет — плоское свойство color.
  4. children у text/button → ошибка: дети только у контейнеров.
  5. Кнопки внутри list/grid без args = '{key}' → все ячейки зовут одну
     функцию с одним литералом и неразличимы.
  6. Ключ хранилища без префикса квеста → прогресс одного квеста течёт в
     другой.
  7. Перерисовка поверхности в onChange каждого символа → поле теряет фокус.
  8. Ожидание, что переменная квеста существует: сначала mnd.vars.has(name),
     иначе заводите свою (mnd.vars.set) и объясняйте это в описании плагина.
  9. mnd.cancel() вне node_enter — не работает: отменяемое событие одно.
 10. Нативная надежда на while-цикл ради анимации: есть бюджет инструкций,
     анимирует движок, а не Lua.

==========================================================================
12. ЧЕК-ЛИСТ ПЕРЕД ПУБЛИКАЦИЕЙ
==========================================================================

  * Права: ни одного лишнего.
  * Манифест: id в две точки-сегмента, sdk = "1", entry указывает на
    существующий *.lua.
  * Хуки: только §5, без дублей.
  * Спеки: ни одного свойства-объекта, ни одного колбэка не-идентификатора.
  * Обработчики — глобальные функции.
  * Ключи хранилища с префиксом mnd.questId.
  * Плагин что-то visibly меняет в поведении квеста: украшение интерфейса без
    логики автору не нужно.
